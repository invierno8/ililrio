# שירות ההערות של Jynx

שירות קטן ויחיד: מחזיק את חוט ההערות המשותף של הדמו, ודוחף כל שינוי לקובץ
`data/jynx-comments.json` שברפו הזה.

## למה הוא קיים

GitHub Pages הוא אחסון סטטי. כדי לדחוף לרפו צריך טוקן, וטוקן שיושב בקוד של דף
ציבורי הוא טוקן שכל אחד יכול לקחת — ואיתו לכתוב לרפו, כולל ל-workflow שרץ
אצלכם. לכן הטוקן יושב כאן, בשירות, ולא בדפדפן. זה בדיוק המבנה של commando
(`data/` מול `client/`), רק קטן בהרבה.

## מה הוא עושה

* משתמשים: מנהלים (Tom ו-ilil) ומעירים רגילים. הרשימה נשמרת ב-`data/jynx-users.json`.
* הערות: קריאה, כתיבה, תגובה, סימון כטופל ומחיקה — הכול על חוט אחד משותף.
* התמדה: כל שינוי נכתב מיד ל-GitHub, כך שגם אם השירות נרדם או מתאפס — ההערות נשארות.

## הרצה מקומית

```bash
cd server
npm install
cp .env.example .env     # ומלאו את הערכים
npm run dev
```

## משתני סביבה

| שם | חובה | מה זה |
| --- | --- | --- |
| `GITHUB_TOKEN` | כן | טוקן עם הרשאת כתיבה ל-`contents` של הרפו הזה בלבד |
| `JYNX_DATA_DIR` | לא | לפיתוח מקומי בלבד, כשאין טוקן: תיקייה שממנה נקראים ואליה נכתבים אותם קבצי JSON, במקום GitHub |
| `GITHUB_REPO` | כן | `invierno8/ililrio` |
| `GITHUB_BRANCH` | לא | ברירת מחדל `main` |
| `JYNX_SESSION_SECRET` | כן | מחרוזת אקראית לחתימת הסשנים |
| `JYNX_PASSWORD_RIO` | לא | הסיסמה של rio. כברירת מחדל `2222`. אם הוגדר `JYNX_PASSWORD_TOM` בעבר, הוא עדיין נקרא כגיבוי |
| `JYNX_PASSWORD_ILIL` | לא | הסיסמה של ilil. כברירת מחדל `1111` |
| `JYNX_REVIEWER_PASSWORD` | לא | סיסמה למעירים; אם ריק, כל אחד יכול להיכנס עם שם בלבד |
| `ALLOWED_ORIGINS` | לא | ברירת מחדל: אתר ה-Pages של הרפו |

## פריסה ל-Render

הרפו כולל `render.yaml`. ב-Render: New → Blueprint → בוחרים את הרפו. אחרי
היצירה ממלאים את ארבעת הערכים שמסומנים `sync: false` בלוח הבקרה של השירות.
בסיום מעתיקים את כתובת השירות ומכניסים אותה כ-`JYNX_API` ב-Secrets של הרפו
ב-GitHub — משם ה-workflow מזריק אותה לבנייה.
