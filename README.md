# RIO · קטלוג האמצעים

דמו חי של מערכת RIO — קטלוג אמצעים, הבעות עניין, ניהול פריטים וניהול מערכת,
בארבע פרסונות. הדמו עצמו רץ בדפדפן בלבד: אין בו API ואין בסיס נתונים — כל
הנתונים הם נתוני הדגמה שב-`src/data`, וכל המצב חי בזיכרון עד לרענון הדף. השירות
היחיד בפרויקט (`server/`) אינו משרת את הדמו אלא את ההערות של Jynx.

המקור הוא `Rio.html` — אב-הטיפוס שנבנה בקנבס העיצוב של Claude. הרפו הזה הוא אותו
אב-טיפוס בדיוק, מפורק לקוד אמיתי: אותם צבעים, אותם גופנים, אותם מרווחים ואותו
טקסט. מה שנוסף הוא מבנה, שלדי טעינה ומעברים עדינים.

## הרצה

```bash
npm install
npm run dev      # שרת פיתוח
npm run build    # בנייה ל-dist/
npm run preview  # תצוגת ה-build
```

## מבנה

```
src/
  main.jsx              נקודת הכניסה — טוען את גיליונות הסגנון ומרכיב את האפליקציה
  App.jsx               מעטפת: תפריט צד, אזור תוכן, שלדי טעינה ומעברי מסך

  design-system/        מערכת העיצוב (Hatal DS) — רכיב לכל קובץ, כמו בפרויקט המקור
    core/               Badge, Button, Card, Icon, Logo
    forms/              Checkbox, Input, QuantityStepper, RadioGroup, SearchBar, Select
    navigation/         Breadcrumb, CategoryNav, CheckoutSteps, Pagination, Tabs
    overlays/           Drawer, Modal, Toast
    commerce/           רכיבי מסחר של ערכת העיצוב (לא בשימוש ב-RIO, נשמרו כמו שהם)

  styles/
    fonts.css           Rubik ו-Heebo, מאוחסנים מקומית (src/assets/fonts) — עובד גם בלי רשת
    tokens.css          טוקנים: פלטה, כינויים סמנטיים, סקאלת טיפוגרפיה, מרווחים, רדיוסים, צללים
    base.css            שכבת הבסיס: קישור משפחות גופנים, קישורים, פסי גלילה
    components.css      סגנונות רכיבי ht-* של מערכת העיצוב
    app.css             ← היחיד שנוסף: שלדי טעינה ומעברי מסך

  data/                 נתוני ההדגמה: פריטים, טקסונומיה, פרסונות, משתמשים, זרעי מסכים
  store/
    RioStore.js         מצב + מנוי לשינויים, ועזרי מיון ושורות
    state.js            מצב הפתיחה
    actions/            הפעולות, מחולקות לפי מסך
    derive/             המרת המצב לערכים שהמסכים מציגים (v)
  screens/              מסך לכל תצוגה, כולל screens/admin לארבעת מסכי המפעיל
  components/           Sidebar ו-Skeleton
  lib/                  עזרי תאריכים והתנהגות ה-style של קנבס העיצוב
```

## איך זה עובד

`useRio()` מחזיר שלושה דברים: `state` (המצב הגולמי), `store` (הפעולות) ו-`v` —
הערכים הנגזרים. הנגזרות (`store/derive`) הופכות מצב לתוויות, לשורות טבלה,
לסגנונות ולמטפלי אירועים, וכל מסך מקבל את `v` ומושך ממנו את מה שהוא צריך. זה
בדיוק המבנה של אב-הטיפוס — שם הכול ישב בפונקציה אחת בשם `renderVals`.

כל מסך מחליט בעצמו אם הוא מוצג, לפי דגל מתוך `v` (למשל `isCatalogScreen`), ולכן
`App` פשוט מרנדר את כולם. אין ראוטר ואין כתובות — בדיוק כמו במקור.

## מה נוסף מעבר למקור

- **שלדי טעינה** (`components/Skeleton.jsx`): שלד פתיחה קצר, ושלד לכל מעבר מסך,
  פריט או פרסונה. כל שלד משרטט את מבנה המסך שנטען, כדי שהמעבר לא יזיז כלום.
- **מעברים עדינים** (`styles/app.css`): הבזק אור על השלד, כניסה רכה של המסך,
  והופעה מדורגת של שורות. הכול מכובה תחת `prefers-reduced-motion`.

שום דבר אחר לא שונה. אין צבע חדש, אין גודל חדש ואין טקסט חדש.

## Jynx

מעל הדמו יושבת Jynx — אותה שכבת הערות שב-commando, בגרסת הערות בלבד: בלי תור
פעולות, בלי ציור, בלי אזכורים ובלי בורר תפקידים. הרכיבים עצמם הועברו משם
(`client/src/devtools/`), ולא נכתבו מחדש: אותה בועה עם הפנים, אותו סרגל, אותה
הילה, אותה קופסת תגובה ואותן נקודות סטטוס.

* **בועה** — צפה, גרירה לכל פינה, ונושמת כשאין מה לעשות. מי שאינו מחובר רואה
  אותה נעולה עם מנעול; לחיצה פותחת את טופס הכניסה.
* **מחזיקים את המקש** — וכל מה שעוברים מעליו מקבל מסגרת סגולה; לוחצים, וקופסת
  ההערה נפתחת על מה שנלחץ. בלי להחזיק העמוד מתנהג רגיל לגמרי. כל עוד הקופסה
  פתוחה, אותו צירוף על אלמנט אחר מוסיף אותו כיעד מקושר בתוך הטקסט.
  השורה שמתחת לסרגל מראה מה המקש כרגע; לחיצה עליה פותחת כרטיס לכידה שממתין
  למקש הבא ומחליף אותו. הבחירה שייכת למשתמש — מי שמחליף מקש משנה רק לעצמו,
  וגם אם מישהו אחר נכנס מאותו דפדפן הוא מקבל את שלו. ברירת המחדל נגזרת
  מהמערכת: ⌘ ב-macOS, Ctrl בווינדוס ולינוקס. ב-macOS זו אינה רק תווית —
  Ctrl+קליק שם הוא לחיצה ימנית ואינו מגיע כאירוע קליק כלל.
* **סרגל** (מספרים 1–4 במקלדת): עין — הילת הריחוף; בועת דיבור — פאנל ההערות;
  מטרה — נקודות הסטטוס על המסך; אנשים — מי יכול להעיר (מנהלים בלבד).
* **נקודות** — נקודה על כל אלמנט שיש עליו הערה: סגולה לפתוחה, ירוקה לטופלה.
  ריחוף מדליק הילה על האלמנט; לחיצה פותחת את ההערות עצמן.
* **פאנל** — מגירה בצד, מסוננת לפי פתוח/טופל, שלי, המסך הזה או כולם, וחיפוש
  חופשי. היא דוחפת את הדמו הצידה במקום לכסות אותו, כך ששום דבר לא מוסתר.
  ריחוף מעל הערה מדליק הילה על האלמנט שעליו נכתבה, ולחיצה עליה לוקחת אליו —
  גם כשהוא במסך אחר או בפרסונה אחרת: Jynx עוברת לשם, ממתינה שהמסך ייטען,
  גוללת אל האלמנט ומהבהבת עליו.

### משתמשים

נכנסים עם סיסמה בלבד, כמו ב-commando: הסיסמה היא הזהות, והשרת יודע לפיה מי
נכנס. לכן שני אנשים אינם יכולים להחזיק את אותה סיסמה, והשרת דוחה ניסיון כזה
בפירוש — אחרת השני היה נכנס לחשבון של הראשון.

rio ו-ilil הם מנהלים: הם רואים הכול, מסמנים ומוחקים כל הערה, ומוסיפים מעירים
דרך כפתור האנשים בסרגל. מעיר שנוסף מקבל שם וסיסמה, מעיר ומגיב, ומוחק רק את מה
שהוא עצמו כתב. מי שאינו ברשימה אינו נכנס — הוא רואה בועה נעולה ותו לא. אין מצב
"נשמר אצלי בדפדפן": החוט משותף או שאינו קיים.

כל אחד מחליף את הסיסמה של עצמו מתפריט ה-Hi (ומאשר בסיסמה הנוכחית), ומנהל
מחליף סיסמה לכל אחד מתוך רשימת המשתמשים, בלי לדעת את הישנה. הסיסמאות נשמרות
כ-scrypt עם מלח אקראי לכל משתמש — הקובץ יושב ברפו ציבורי. הסיסמאות הראשונות
של המנהלים מגיעות מ-`JYNX_PASSWORD_RIO` ו-`JYNX_PASSWORD_ILIL`, ומרגע שהוחלפו
מתוך Jynx הרשימה היא הקובעת.

### איפה ההערות נשמרות

בשירות שב-`server/`, והוא דוחף כל שינוי ל-`data/jynx-comments.json` שברפו הזה.
הדפדפן מסנכרן כל שש שניות, כך ששני אנשים על אותו מסך רואים אחד את ההערות של
השני בלי לרענן.

Pages מגיש קבצים סטטיים בלבד. כדי לכתוב לרפו צריך טוקן, וטוקן שמוטמע בדף ציבורי
הוא טוקן שכל אחד יכול לקחת — ולכן הטוקן יושב בשירות. הוראות הפריסה:
`server/README.md`. כתובת השירות נכנסת לבנייה דרך משתנה `JYNX_API` ברפו.

## מובייל

המערכת בנויה למסך רחב. מתחת ל-900 פיקסלים מוצגת במקומה הודעה שמפנה למחשב,
במקום פריסה שבורה.

## שתי הערות על נאמנות למקור

- `style` שנכתב על רכיב של מערכת העיצוב לא השפיע באב-הטיפוס: מנוע הקנבס הסיר
  אותו והשאיר ממנו רק מאפייני מיקום. שני מקומות במסך "המעקבים שלי" מסתמכים על
  זה (כפתורי "הסר" שנועדו להיות אדומים ונשארו כחולים). `lib/hostStyle.js` משחזר
  את ההתנהגות. אם תרצו שהסגנון כן יחול — העבירו אותו ישירות כ-`style` לרכיב.
- הבדיקה שנעשתה: צילום של כל מסך בדמו מול אותו מסך באב-הטיפוס, והשוואת פיקסלים.
  שנים-עשר המסכים הראשיים יוצאים זהים לחלוטין.
